# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Personal portfolio: Astro 7 + React 19 + Tailwind 4 (via `@tailwindcss/vite`), pnpm, static output. Implements the "Signal" design (one-page, dark/light, EN/ES).

## Commands

- `pnpm dev` — dev server on :4321 (`astro dev --background` per AGENTS.md; manage with `astro dev status|logs|stop`)
- `pnpm build` / `pnpm preview`
- `pnpm lint` / `pnpm lint:fix` — ESLint flat config (`eslint.config.js`)
- `pnpm format` / `pnpm format:check` — Prettier (astro + tailwind class sorting plugins)
- `pnpm exec astro check` — type check; requires `typescript@6` (TS 7 breaks both `astro check` and typescript-eslint, so don't bump it)
- `pnpm dev:api` — the voice Worker (`wrangler dev` on :8787; `astro dev` proxies `/api` to it). Needs `.dev.vars` (see `.dev.vars.example`; `MOCK_OPENAI=1` fakes OpenAI). `pnpm check:worker` type-checks `worker/`. Don't run `pnpm deploy` (`astro build && wrangler deploy`): production deploys itself from `main` (see Deploy).

No test suite.

## Architecture

- **i18n on one URL, switched without reload.** All copy lives in `src/i18n/content.ts` (`EN`/`ES` objects plus per-language arrays built by `build(isEs)`; ES is typed `typeof EN`, so add copy to both). `getContent()` in `src/i18n/index.ts` zips both languages: every string becomes a `Txt` (`string`, or `{ en, es }` when they differ). Render text with `<T v={...} />` (emits `<span lang="en">` + `<span lang="es">`; CSS in `global.css` hides the inactive one via `html[data-lang]`). Attributes (`aria-label`, `alt`, `title`) go through `{...attrs({ 'aria-label': txt })}`; string work on a `Txt` uses `pick`, `both`, `splitTxt`. Never render a `Txt` with `{x.foo}` directly (it prints `[object Object]`).
- **CV download:** the header's "My CV" button (`Header.astro`) is a `<details>` picker with the English and Spanish PDFs (`/cv/Juan-Londono_AI-Engineer{,_ES}.pdf`, `CV_PDF_EN`/`CV_PDF_ES` in `src/lab/chat/cv.ts`, downloaded under those names, the page's language listed first); the mobile menu shows both as buttons. The chat cites the English one. The Worker serves `/cv/*` (`worker/cv.ts`, `run_worker_first`) from the private CV repo (`CV_REPO`, files `dist/base.{en,es}/…pdf` on `main`, built there) through the GitHub API with the `CV_GITHUB_TOKEN` secret (fine-grained, Contents read-only on that repo), cached at the edge for an hour, so a CV change reaches the site without a deploy; without the token or when GitHub fails it serves `public/cv-fallback/` (response header `X-CV-Source: github|fallback`).
- **Titles and icons:** the tab title follows the language (`title` prop of `Layout.astro` takes `{ en, es }`, swapped by the inline script and `setLang`); the favicon is Sophie's orb (`public/favicon.svg`) and the navbar mark next to JUANDLCH is a `</>` icon.
- **Preferences:** the inline script in `Layout.astro` sets `data-theme` and `data-lang` before paint (`?lang=` → `localStorage` → browser language). `src/scripts/prefs.ts` handles the EN/ES buttons (`data-set-lang`), swaps `data-i18n-attrs`, and syncs other open tabs through the `storage` event. Any new page must use `Layout.astro` to share them. `/en` and `/es` redirect to `/?lang=…` (`astro.config.mjs`).
- **Sections are Astro components** (`Header`, `Hero`, `Work`, `Lab`, `Rag`, `Stack`, `About` (wraps `Leading`), `Principles`, `Certifications`, `Footer`) receiving slices of the content object. The only React island is `ThemeToggle.tsx`. `SophieDock.astro` floats bottom right on the landing (plain script, no island): a mini Sophie orb whose eyes follow the pointer and blink, with a bubble that types a few lines (`sophieLines` in `content.ts`, `|`-separated) and links to the voice lab; `BackToTop` is stacked above it, so keep their offsets in sync.
- **Theming:** colors are CSS variables in `src/styles/global.css` (`:root` = light, `:root[data-theme='dark']` = dark), exposed to Tailwind through `@theme inline` (`bg-panel`, `text-accent`, `border-line2`, …). Use these tokens, not raw hex. `Layout.astro` has an inline script that sets `data-theme` from `localStorage` before paint (`localStorage`, else the system `prefers-color-scheme`, dark if unreadable); `ThemeToggle` observes that attribute via `useSyncExternalStore`.
- **Sizing is fluid.** Spacing and type come from tokens in `global.css` (`@theme`): `py-section`, `mt-block`, `gap-stack`, `p-card`, `gap-gutter`, `text-display|hero|h2|lead|h3|sub`, `h-wave`, `size-icon|badge`. They use `clamp()` with `vw` and `svh` so layout compacts on small/short screens. Don't add fixed px paddings/font sizes for layout; page width is `max-w-[1200px]`, anchors offset by `--header-h`.
- **Security headers** for the static pages are in `public/_headers` (HSTS, nosniff, no framing, referrer and permissions policy); the Worker's own responses don't get them.
- Shared look helpers (`.dots`, `.eyebrow`, `.jd-card`, `.jd-fill`, animations) are in `global.css`; `Waveform.astro` generates bar heights in the frontmatter and animates with CSS only.

One file per message (a new pick replaces it); only the document agent's Knowledge Base takes several at once (5 files, PDFs up to 20 pages, same size cap). ## Chat on the site's key

- `BYOK` in `src/lab/chat/cases.ts` is **off**: the chat runs on the site's key and every key option is hidden (header keys button and dialog, no-key banner, `caseNeedsKey`, the intro's "run it yourself"; the code stays for later). With it on, visitors paste their own keys and the SDK calls the provider directly, as before.
- The browser still runs the turn loop and tools (`openai-chat.ts`), but `getClient('')` points the OpenAI SDK at the Worker (`baseURL` `/api/chat/v1`) with `labToken` as its key (`src/lab/chat/lab.ts`: a 2 h token from `POST /api/chat/session` after Turnstile, bound to the IP hash, kept in memory only). Voice notes go to `/api/chat/v1/audio/transcriptions` the same way.
- `worker/chat.ts` pins each request to its case (`X-Lab-Case` → `CASES`): `instructions`, model, `max_output_tokens`, allowed efforts, and the case's own `clientTools` as function tools, built from `tool-defs.ts` (the page's copy is ignored), so the key can't run anything else. `input` may only hold user/assistant messages, reasoning, function calls and their outputs (no system/developer items), images inline with detail auto/low/high; OpenAI's errors reach the page as their code only. Each request **reserves** its worst cost in `Quota` (one DO per UTC day; output budget + input estimated from the body), at most 2 in flight per IP, and **settles** to the real cost from `usage` in `response.completed` (prices in `worker/prices.ts`); with no usage the reservation stays. A request ending in a user message counts as a message. Limit responses are 429 `{ error: { code: 'chat_limit_ip' | 'chat_limit_day' | 'chat_busy' } }` with `x-should-retry: false`; they show as the `chatLimitIp` / `chatLimitDay` notices with a "Book a call" fix.
- **Rate limit:** every `/api/*` request but `/api/voice/end` (a refused hangup would leave the call running) passes `API_LIMIT` (Workers rate-limiting binding in `wrangler.jsonc`: 60 per minute per IP hash), a 429 `rate` past it. It only stops scripts; the quotas below cap spending.
- **Limits** (`wrangler.jsonc` vars; `.dev.vars` lifts them in dev): chat 60 messages and $0.40 per IP per day, $10 per day for the whole site (raised from $3 for the LinkedIn launch, Nov 2026), 30 messages per conversation; voice 1 call of 5 min per IP, 40 calls a day site-wide (from 20), and a $0.30 cost cap per call (`VOICE_CALL_USD`, summed from each `response.done` usage in the sideband; `max_output_tokens` 600, 50 responses). Max for one visitor using everything: ~$0.70/day; worst day for the site: ~$23 (chat $10, voice 40 × $0.30, insights $1). The copy mentions "60 messages": keep it and `CHAT_MSGS_PER_DAY` (`src/lab/chat/lab.ts`) in sync with `CHAT_MSGS_PER_IP`, and the voice lab's `limits` line (`src/i18n/voice.ts`) with `MAX_PER_IP`/`SESSION_S`.
- **Usage meter:** under the composer (instead of the keys line while `BYOK` is off) the chat shows messages left today (shared by every case and the CV chat) and left in this conversation, always, warning at 5 or fewer. The Worker sends the day's remainder as `X-Lab-Left` on every `/responses` reply and as `left`/`max` with the session token; `labFetch` (the SDK's `fetch` on the site's key) stores it in `$chatLeft` (in memory). Until the first message it shows the static limit (asking earlier would need Turnstile); a `chat_limit_ip` sets it to 0. Dev's `.dev.vars` lifts the limits, so the numbers are huge there. Limits are per IP (an IPv6 counts as its /64, `ipKey` in `worker/http.ts`), so people on one network share them.

## Voice lab

- `/lab/voice` (`src/pages/lab/voice.astro` → `VoiceApp.tsx`): talk to **Sophie**, a GPT Realtime agent over WebRTC grounded in the same profile as "Meet my AI". Unlike the chat it's open (no BYOK) and runs on Juan Diego's key, so the browser never gets a key or token: it posts its SDP offer to the Worker, which creates the call server side.
- **Worker** (`worker/`, `wrangler.jsonc`; serves `dist/` as static assets and runs first on `/api/*`). `POST /api/voice/session` checks `Origin` against `SITE_ORIGIN`, verifies Turnstile (fresh token per Start, `src/lab/voice/turnstile.ts`), reserves quota in `VoiceQuota` (one Durable Object per UTC day: `MAX_PER_IP` per IP as an HMAC with `IP_SALT`, `MAX_PER_DAY` in total, one active call per IP), builds the session (`worker/openai.ts`: model `VOICE_MODEL`, voice `VOICE_NAME`, `semantic_vad`, transcription for captions, the one tool) and calls `POST /v1/realtime/calls`. `VoiceCall` (one DO per call id) owns the hard cutoff: an alarm at `SESSION_S` + 5 s that calls `/v1/realtime/calls/{id}/hangup`, and a sideband WebSocket that hangs up if the client changes the session (instructions, tools, voice, `max_output_tokens`), adds a system message other than the page's own (`SYSTEM_NOTES` in `worker/call.ts`: add any new one there) or exceeds 50 responses; if the sideband can't connect (two tries) the call doesn't start (hung up, quota given back, `unavailable`). `POST /api/voice/end` hangs up (only from the IP that started it). Secrets: `OPENAI_API_KEY` (from an OpenAI project with a monthly budget cap), `TURNSTILE_SECRET`, `IP_SALT`; the sitekey goes in `PUBLIC_TURNSTILE_SITEKEY` at build time.
- **Prompt** in `src/lab/voice/prompt.ts` (plain TS, imported by the Worker; shared blocks in `src/lab/chat/prompts.ts`). The profile goes inline (no retrieval tools, for latency): the Worker builds it with `profileText(cv)` from `profile.ts` when each call starts, from the live CV (`liveCv` in `worker/cv.ts`) plus the portfolio copy, build, stories and notes (`profile-sections.ts` keeps the section list free of browser code so the Worker can import the profile). The only tool, `show_contact_options`, is answered by the client (`src/lab/voice/rtc.ts`) and drawn with the chat's `ContactActions` (`src/components/lab/ui.tsx`, shared with `ChatApp`).
- The page opens with a **recorded greeting** (`src/assets/lab/voice/greeting-{en,es}.mp3`, recorded by `scripts/voice-greeting.mjs` with the live agent's own Realtime model and voice (`VOICE_MODEL`/`VOICE_NAME` from `wrangler.jsonc`, not the TTS API, which sounds different), reading `greeting` from `src/i18n/voice.ts` and checking the transcript against it; regenerate when the text, model or voice changes), captioned word by word as it plays. It autoplays when the browser allows it (arriving from the landing through `ClientRouter`); otherwise it plays on the first click or key anywhere but Start. Start stops it and the agent is told not to greet again.
- **Budget and resume:** the 5 minutes are a budget per session, shown as a countdown in the orb. Ending a call (or a drop) with ≥ 10 s left offers **Resume**: the Worker's `VoiceCall` keeps `{ ip, used }` for 30 min after the end, `takeResume` hands the rest to a new call that doesn't count against the quota (`VoiceQuota.hold`), and the client replays the transcript as text items so Sophie keeps the thread. **Start over** clears the conversation but keeps the time left (with one call a day it goes on as a resume, without the transcript). 20 s before the end the client asks Sophie to wrap up; at 0 it hangs up (the server cuts a few seconds later anyway). Leaving the page ends the call.
- Layout from the **Voice board** of the design canvas (`project/Voice.dc.html`): `SophieOrb.tsx` (the board's orb: 60 rays, rings while she speaks, a dashed ring while she thinks) with Sophie's face in the core (capsule eyes drawn as paths that become `^ ^` when she smiles: a base expression per state, plus gestures VoiceApp fires with `emote()`: wink on the greeting, joy on connect, on thanks (`THANKS`) and on contact talk (`CONTACT_TALK`) in the visitor's words, contact (look at the buttons, hop, sparkles) on `show_contact_options`, surprise on barge-in, a glance at the clock on wrap-up; sad eyes when a call fails), all moved by rAF from the mic and Sophie's voice (`AnalyserNode`s), no React renders; a live caption, 60px controls, and the transcript (turns, `tool` and `barge-in` events) with live metrics (connect, last turn, barge-ins, session) in a side panel that becomes a sheet under `narrow`. Reduced motion keeps only the shape per state. Copy in `src/i18n/voice.ts`. In an app's built-in browser (LinkedIn, Instagram, Facebook, WeChat, Line, Android WebView: `inApp` in `VoiceApp.tsx`, by user agent) a line under Start says the mic may not work there and offers to copy the link, and a mic failure says to open the page in Chrome or Safari.

## Metrics

- **Page views (people only):** every public page posts its path (and, on arrival, the referrer) to `POST /api/hit` (`src/scripts/hit.ts`, on `astro:page-load`, no cookies or ids; skipped on `noindex` pages and in the owner's browser, marked `jd-owner` in `localStorage` when `/admin` loads, with a toggle there). `worker/hits.ts` stores a `page_view` event: subject the path, `detail` `human` or `bot:ua` (bot/script/headless user agent) / `bot:automation` (`navigator.webdriver`) / `bot:datacenter` (`cf.asOrganization` of a cloud or hosting provider; not Akamai/Cloudflare/Fastly, which carry iCloud Private Relay and WARP users), `n` 1 when the visit starts there (referrer not this site), `ref` the referring host, and the country. No IP or user agent is stored. Messaging apps aren't treated as bots (their previews don't run JS; their in-app browsers carry their names).
- **Web Analytics (reference):** Cloudflare Web Analytics (cookieless). `Layout.astro` adds the beacon (`spa: true`, for `ClientRouter`) only when the build var `PUBLIC_CF_BEACON_TOKEN` is set, so dev doesn't count. Don't also turn on the dashboard's automatic injection (double counts).
- **Lab usage and messages:** `worker/metrics.ts` writes to D1 (`LAB_DB`, `portfolio-analytics` in `wrangler.jsonc`; the Worker creates the tables on first use). `events`: `chat_session`, `chat_message` (subject: case id, or `cv` for the meet case on `/lab/cv`; `detail`: the conversation id, every case), `chat_limit`, `chat_cost` (USD in `n` per request, settled from usage, or the reservation without one; subject: case or `voice_note`), `voice_call`, `voice_resume`, `voice_end` (reason, seconds), `voice_cost` (the call's USD). Each carries the visitor's `country` (Cloudflare's `cf.country`, two letters; added with `ALTER TABLE` in `metrics.ts`, since the table predates it). `messages`: every message the visitor writes in the meet case (lab chat and CV chat) and Sophie's transcribed visitor turns (`VoiceCall.watch`), grouped by `conv` (the chat's in-memory `ChatSession.conv`, sent as `X-Lab-Conv`; voice: the first call of a resume chain). No IPs, emails and phone numbers masked (`redact`), deleted after 180 days by the daily cron (`scheduled` in `worker/index.ts`). Writes never fail a request. The chat (meet case) and the voice lab say so in a `stored` line (`src/i18n/chat.ts`, `src/i18n/voice.ts`); keep it if more text is stored.
- **Daily insights** (`worker/insights.ts`, taxonomy in `src/lab/insights/taxonomy.ts`, shared with the dashboard): the `10 5 * * *` cron (00:10 Bogotá, keep in sync with `DAILY` in `worker/index.ts`) prunes and sends the previous Bogotá day's conversations to the OpenAI Batch API (labeled by `INSIGHTS_LABEL_MODEL`, Luna; capped by `INSIGHTS_MAX_CONVS` and the estimated `INSIGHTS_USD_PER_DAY`); every cron run (also hourly at :40) moves `daily_reports` along: `labeling` → ingest (`message_labels` with fixed category and intent, `message_topics` with free topics reused from `topics`, `conversation_goals`) → `reporting` (one direct call to `INSIGHTS_REPORT_MODEL`, Sol, writes the Spanish report) → `done` (or `empty` / `failed` after 3 attempts). Anti-hallucination is in code: labels must cover exactly the messages sent (else one direct relabel, then unclassified = NULL), citations are message ids checked against the ones given, counts come from SQL (`stats`), report items about unknown topics/goals or uncited are dropped, and reports store ids, never visitor text. Free plan: little CPU and 50 D1 queries per invocation, so one day per run and JSON-parameter inserts (`json_each`). Test locally with `wrangler dev --test-scheduled --var MOCK_OPENAI:1` and `/__scheduled?cron=10+5+*+*+*`.

- **Dashboard** (`/admin`, `src/pages/admin.astro` → `src/components/admin/AdminApp.tsx`, copy in `src/i18n/admin.ts`): KPIs (CV chat and Sophie: conversations, messages, messages per conversation, voice calls), messages per day (tooltip with the day's cost), categories, goals, top topics, intents, use per demo (messages and conversations of every case), countries of demo users (map and bars), costs per part (chat per case, voice notes, calls, insights; per conversation or call), and site visits by people from the own counter (visits per day or hour, a visitor map, top pages, referrers, bots left out by reason, and visit-to-use per demo page), with Web Analytics' unfiltered total as a reference (`GET /admin/api/traffic` queries the GraphQL Analytics API with the `CF_ANALYTICS_TOKEN` secret, Account Analytics Read, and `CF_ACCOUNT_ID`/`CF_SITE_TAG` vars; sampled estimates, cached 5 min; hidden without the token). A range bar filters everything: presets (today, 7/30/90 days), a month, from/to dates, or a click on any day's column (`from`/`to` Bogotá days, at most a year). The world map is projected at build time in `src/lab/insights/world.ts` (world-atlas + d3-geo, ISO alpha-2 ids) and passed to the island as SVG paths (single-series accent bars with values and a table view), and the daily reports with each cited message quoted from D1 by id, every message of the day with its labels, and a "run this day again" button (`POST /admin/api/rerun`, same origin only). Cloudflare Access (team `ACCESS_TEAM`, app `ACCESS_AUD` in `wrangler.jsonc`) guards `juandlch.dev/admin*`; in case another route reaches the Worker without Access (workers.dev, if turned back on), `worker/admin.ts` also verifies the Access JWT (`Cf-Access-Jwt-Assertion`: RS256 against the team's certs, `aud`, `iss`, `exp`) on every `/admin/api/*` request (`run_worker_first`). `Layout`'s `noindex` adds robots `noindex` and drops the analytics beacon. Visitor text and model output render as plain text only. Dev: `pnpm dev:api --var ADMIN_DEV:1` (honored on localhost only; `astro dev` proxies `/admin/api`).

## Deploy (Cloudflare Workers Builds)

- Production is the Worker `juandlch-portfolio` at https://juandlch.dev (custom domain, bought on Cloudflare Registrar; the workers.dev route is off, `workers_dev: false`), connected to GitHub through Cloudflare Workers Builds: **every push to `main` (a merged PR) builds and deploys automatically** (`astro build`, then `wrangler deploy`). Never ask the user to run `pnpm deploy` or `wrangler deploy`; to ship, merge the PR and wait a minute or two. Wrangler has no login in this environment.
- **Runtime vars live in `wrangler.jsonc`** (`vars`). Each deploy replaces the dashboard's plain-text Variables with them, so a value set only in the dashboard is wiped (that's how an empty `SITE_ORIGIN` refused every session with 403 `origin`). Change them in `wrangler.jsonc` through a PR. `SITE_ORIGIN` lists the allowed origins comma-separated (only `https://juandlch.dev` now).
- **Secrets** (`OPENAI_API_KEY`, `TURNSTILE_SECRET`, `IP_SALT`) go in the Worker's **Settings → Variables and Secrets** (runtime) with type **Secret**: secrets survive deploys and apply without one. Not in **Settings → Build → Variables and secrets**: build variables only exist while building and the Worker never sees them (a missing `TURNSTILE_SECRET` shows as 403 `captcha`, "We couldn't check that you're not a bot").
- **Build variables:** only `PUBLIC_TURNSTILE_SITEKEY` (Astro inlines it at build time); no secrets there. The Turnstile widget's hostnames must include the production host.
- To check a deploy from here: `curl -X POST <site>/api/voice/session -H 'Origin: <site>' -d '{}'` answers 400 `bad_request` when the origin is accepted (403 `origin` if not).

## Images

- AWS icons are official SVGs in `src/assets/aws/` (sourced from the JuanDLCH profile repo; `sns.svg` from the design). `Stack.astro` resolves them via `import.meta.glob` to hashed URLs. Run `pnpm optimize:svg` (SVGO, `svgo.config.mjs`) after adding any SVG.

## Development rules

- `main` is protected: no direct pushes. Work on short-lived branches named `<type>/<slug>` (e.g. `feat/hero-photo`), open a PR, and squash-merge once the `verify` CI check (`.github/workflows/ci.yml`: lint, format check, `astro check`, build) passes. The PR title becomes the commit message, so it must be a Conventional Commit. Branches are deleted on merge.
- Commits follow Conventional Commits (`commitlint.config.js`): `feat`, `fix`, `content` (copy changes), `style`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `chore`, `revert`. English, imperative, header ≤ 72 chars. One logical change per commit.
- Husky hooks: `pre-commit` runs lint-staged (ESLint + Prettier on staged files); `commit-msg` runs commitlint. Don't bypass with `--no-verify`.
- Colors come from theme tokens (`text-accent`), never raw hex. New copy goes in `src/i18n/content.ts` for both languages. No `any`.
- Dependabot ignores TypeScript major bumps (see TypeScript note above).
